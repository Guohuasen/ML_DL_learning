# 论文精读提示词（可复用模板 · v4.3）
> 同步说明：本提示词由 Codex 生成并维护，同时保存于 D:\Python程序\ML_DL_learning\LearningPrompt\，随该仓库推送到 GitHub（Guohuasen/ML_DL_learning）

> 使用方法：把尖括号 <...> 里的内容替换成实际论文信息即可。
> v4.1 更新：把"面向知识空白读者"写成硬性要求——概念必须从零建立体系、必须配具体数字演示、类比不能替代公式与例子。

---

请用「宏观 → 逐层 → 细节」的方式讲解这篇论文：<论文标题 / 文件路径>。

我读论文是为了学知识，不是做英语阅读理解，也不是揣测作者意图。**我是知识与论文阅读的"双小白"**：脑子里没有现成的知识体系，默认我什么都没有，从头建立。

【讲解流程（每个部分固定 6 步）】

1. **英文原文**：先把这一部分的英文原文完整输出（可分段），让我先看原版。
2. **整体印象**：2 分钟鸟瞰——这部分在全论文里扮演什么角色、大概说了什么。
3. **逐句翻译拆解**：原句 → 逐词/逐短语中文对应 → 整句通顺翻译 → 这一句里值得注意的知识点。
4. **🧠 知识层（重头）**：见下方【知识层硬性要求】。
5. **术语卡片**：英文术语逐词讲：词源拆解（助记）→ 中文含义 → 定义 + 例子 + 一句话直觉。
6. **一页纸总结 + 一分钟回顾**。

【知识层硬性要求】

- **从零建体系，不成知识点堆砌**：每个概念从"没有它行不行 / 为什么需要它"讲起，按"问题 → 方案 → 还不够 → 下一个问题"的链条组织；明确"上一步解决了什么、这一步还缺什么"。
- **每个关键机制必须配具体数字演示**：编一个小例子（小维度如 d=4、两三个 token），把输入值、计算过程、输出值都用数字写出来，让我亲眼看到结果（如 embedding 查表、embedding+位置编码逐元素相加、残差 x+F(x)）。
- **类比不能替代解释**：比喻只作辅助，后面必须紧跟公式和数字例子。比如"残差=抄近道"这种话必须接着写出 x + F(x) 并演示。
- **论文记号要标明"状态"**：某个符号（如 xₙ ）在这一刻到底是原始 token、embedding 向量、还是 embedding+位置编码之后的向量，要用"数据流阶段标注"讲清楚（原始词 → 查表 → 加位置编码 → 进第一层）。
- **公式不得裸放**：任何公式出现，必须当场解释每个符号的含义（上下标、字母角色）、输入输出形状和整体作用，并配数字演示或工作流说明；若该运算属于后面才教的，先给一句话直觉，再说明"推导在后面"。不许"先摆公式、回头再讲"。
- **术语首次出现给"定义 + 例子 + 类比"三件套**。
- 我问"这是什么"时，先给直觉，再给准确定义，再给例子。

【讲解风格】

- 易混概念用表格；抽象概念用类比+数字例子；关键设计讲"为什么"。
- 按顺序记忆的知识，先讲根本原因或分类依据，让清单从原理里自然推导出来。
- 主动提醒常见坑和易误解点（歧义译文、论文内部数据不一致、易混符号等）。
- 我指定重点时，其他内容一句话带过，不平均用力。

【小步递进】每次只讲一小块，讲完就停，等我确认再继续。每轮开头标明"当前第几步 / 论文走到哪了"，结尾问是否继续下一步。

【数学公式渲染要求（硬性）】行内符号一律用 Unicode（hₜ , xₜ , dₖ , √ , ᵀ , ·），符号后若紧跟标点就在符号与标点之间加一个半角空格（英文原文引用同样处理）；只有独立成行的重点公式才用 $$…$$；输出前自查：正文里不得出现裸的 $、\、下划线。

## 附录 A：为什么聊天里行内 $…$ 不渲染（根因备忘，2026-09-06 实机查证）

本机 Codex 桌面版 26.901.5280.0 的聊天渲染器把 markdown 管线配置为：
remarkPlugins: [[remarkMath, { singleDollarTextMath: false }]], rehypePlugins: [rehypeKatex]，
即行内 $…$ 被硬编码禁用，只有 $$…$$ 可用；config.toml 无此开关。→ 行内符号用 Unicode，独立公式用 $$…$$。另有离线排版版笔记（KaTeX→MathML）可对照复习。
