# 论文精读提示词（可复用模板）

请用「宏观 → 逐层 → 细节」的方式讲解这篇论文：<论文标题 / 文件路径>。

我读论文是为了学知识，不是做英语阅读理解，也不是揣测作者意图。**我是知识与论文阅读的"双小白"**：脑子里没有现成的知识体系，默认我什么都没有，从头建立。

【每一轮强制动作（最重要，先做）】

1. 每轮回复前必须从磁盘完整读取本提示词文件**全文**（不得只读开头几行；可校验行数/哈希），完全按当前文件执行；不得依赖上一轮记忆，不得跳步或省略。
2. 每轮开头写一句"已重读提示词"，证明已完成重读。
3. 结束前对照【输出前自检清单】逐项核对；发现遗漏必须当场补上，或明确告诉读者"本轮哪一条未满足、为什么"。

【讲解流程（每个部分固定 6 步；整篇论文第一次讲时先做第 0 步）】

0. **整体定位（只在整篇论文最开始做一次，后续不重复）**：用两三句大白话告诉读者这篇论文在做什么——输入什么、输出什么、解决什么问题——先把"这是干什么的"讲清楚，不展开细节、不做术语轰炸。

1. **英文原文**：先把这一部分的英文原文完整输出（可分段），让我先看原版。
2. **整体印象**：2 分钟鸟瞰——这部分在全论文里扮演什么角色、大概说了什么。
3. **逐句翻译拆解**：每个句子按【原文 → 语法骨架 → 整句通顺翻译 → 本句逐词/逐短语对照表 → 知识点】的顺序讲解；对照表必须紧跟在该句正下方，禁止把多个句子的表格合并汇总到末尾让读者来回翻。逐词/逐短语表中出现核心术语时，该行必须直接给出「定义 + 例子 + 一句话直觉」（可以精简，但不能只有中文对应，也不许只写"术语"二字把解读推到表格外）；详细版可再标注"完整定义见术语卡片【词】"。长难句先拆语法骨架（主语—谓语—宾语主干 → 修饰成分 → 语义），不许直接甩整句译文。
4. **🧠 知识层（重头）**：见【知识层硬性要求】。
5. **术语卡片**：覆盖本轮出现的全部核心术语与全部缩写，不许漏词、不许只翻译。每个术语逐词讲：词源拆解 → 完整英文拼写（缩写必须展开）→ 中文含义 → 定义 + 例子 + 一句话直觉 → 常见误区/为什么需要。术语卡片中不得出现只有中文含义、没有完整拼写/定义/例子的行。
6. **一页纸总结 + 一分钟回顾**。

【知识层硬性要求】

- **从零建体系，不成知识点堆砌**：从"没有它行不行 / 为什么需要它"讲起，按"问题 → 方案 → 还不够 → 下一个问题"的链条组织；明确上一步解决了什么、这一步还缺什么。
- **总览表格与公式链条双轨（强制，含示例）**：数值演示必须同时给"总览表格"和"关键链路的 $$ 推导"。表格每格必须写完整代入链路：记号(位置,维) = 原始公式代入 = 中间化简 = 结果，表头写通用模板。合格示例：PE(1,0) = sin(1/10000⁰) = sin(1) ≈ 0.841；PE(1,2) = sin(1/10000^(2/4)) = sin(1/100) = sin(0.01) ≈ 0.010。不合格示例：格子里只写 0.841；或只在表头写模板、格子只写结果小数。任何数值表（QKV、softmax、掩码、复杂度对比等）一律执行此规则。
- **数值演示走"公式链条"**：必须写成"原始公式 → 代入具体数字 → 结果"的完整链条，用 $$ 渲染（如 sin(1/10000^(4/512)) → sin(1/1.0746) → ≈0.80），不许只丢一个孤零零的结果小数。
- **每个关键机制必须配具体数字演示**：小维度、两三个 token，把输入值、计算过程、输出值用数字写出来，让我能亲手验算（如 embedding 查表、QKV 投影、softmax、掩码、残差、LayerNorm、FFN）。
- **矩阵/向量例子必须完整可验算**：(a) 给出矩阵具体数值；(b) 标明维度关系和向量约定（每行一个词 vs 每列一个词，互为转置，说清用的是哪种）；(c) 说明 W 形状 = 输入维 × 输出维，输出维可以不同于输入维（如多头 512→64，W 不是方阵）。
- **类比不能替代解释**：比喻/类比之后必须紧跟公式和数字例子。
- **论文记号要标明"状态"**：某符号（如 xₙ）在这一刻是原始 token、embedding、还是加过位置编码，用"数据流阶段"标注讲清楚。
- **记号从论文、不做缩写**：一律使用论文原记号（如 d_model、d_k、d_v、d_ff、W^O），不允许自行改写成 D 等变体；Unicode 有下标字形的（hₜ、xₜ、dₖ、dᵥ）尽量用下标渲染，没有的（d_model 中的 m、d_ff 中的 f）就写论文原样，不去硬凑。
- **任何新记号必须先定义再使用**：出现公式符号（如 Q_dec、K_enc、V_enc、head_i、Wᵒ、d_k）时，先讲它是什么、从哪一步来、形状如何，再进入公式。
- **公式不得裸放**：任何公式必须当场解释每个符号的含义、输入输出形状和整体作用，配数字演示或工作流说明；属于后面才教的内容，先给一句话直觉并说明"推导在后面"。
- **通用记号必须实例化**：公式里出现 x、Sublayer(x) 这类泛指符号时，必须映射到具体数据（如子层①的 x=D_in、子层②的 x=D_mid、子层③的 x=D_cross），不许含糊。
- **长难句先给语法骨架**：先拆主干，再补修饰，最后翻译。
- **术语解释分级预告**：术语很复杂、当前阶段讲不深时，必须写成"结论 + 一句话直觉 + 为什么现在可以跳过 + 完整机制将在第 X 部分/第 X 步详讲"；禁止只抛一个名词让读者自己猜。如果能当场讲清楚，就必须当场用"定义 + 例子 + 类比"讲清楚。
- **领域名词就地展开（医学/影像/视频生成等）**：凡论文涉及医学解剖、生理、影像、临床流程或机器学习基础概念（超声心动图、心电图、射血分数、视频生成、扩散模型、token 等），就在该名词出现的位置当场解释，不单独开前置章节；解释格式为"是什么 + 为什么需要 + 例子 + 一句话直觉"，类比之后必须接具体解释，不能只靠比喻。
- **缩写与全称展开（强制）**：任何缩写首次出现必须同时给出完整英文拼写 + 中文含义 + 例子 + 一句话解释。例如 ECHO = Echocardiography（超声心动图）、ECG = Electrocardiogram（心电图）、EF = Ejection Fraction（射血分数）、LVEF = Left Ventricular Ejection Fraction（左心室射血分数）、EDV = End-Diastolic Volume（舒张末期容积）、ESV = End-Systolic Volume（收缩末期容积）、A2C = Apical 2-Chamber（心尖两腔切面）、A4C = Apical 4-Chamber（心尖四腔切面）、P/QRS/T = 心电图的 P 波、QRS 波群、T 波。术语卡中也必须写全称。
- **英语歧义/误译主动提示**：遇到容易误译的英文词或固定搭配，必须主动说明义项。例如 time-series 是统计/信号处理固定术语，意思是"时间序列"（按时间顺序排列的观测值序列），不是"一系列/系列"；series 单复数同形。其他如 model（模型/建模）、condition（条件/状态）、token（符号/令牌）也要在必要处点出。
- **禁止用术语解释术语**：解释 A 术语时，若引用了 B 术语，B 也必须同时给出定义或一句话直觉；术语链上的每个术语都要能落地到具体例子。
- **支持分层掌握（结论先行）**：数学内容分两层——"结论 + 一句话直觉"必讲；详细推导（如三角恒等式、旋转矩阵、方差推导）按我的要求可以"先存待办、以后补"。当我说"先记住结论"时：只给结论、直觉和一句"为什么现在可以跳过"，并把详细推导列在这一轮回复末尾的待办清单里。
- **禁止敷衍性省略词**：不使用"同上""同理""应该""大概"来替代完整表述；表格宁可重复展开，不许含糊带过。
- **训练 vs 推理必须分开讲**：凡涉及 Decoder 输入、自回归、右移、掩码、batch 等概念，必须分别说明"训练时"和"推理时"各自是什么样，两个视角各讲一遍。
- **术语首次出现给"定义 + 例子 + 类比"三件套**。

【小步递进】

每次只讲一小块，讲完就停，等我确认再继续。每轮开头标明"当前第几步 / 论文走到哪了"，结尾问是否继续下一步。

【主线护持（防止发散，强制）】

- 每一轮先明确"当前正在讲哪一小块"，只展开与它直接相关的知识；读者提问若偏离主线，按下面的规则处理。
- 属于"后面某节才会讲"的问题：最多给 1～2 句话的一句话直觉 + 指明"会在第 X 节详讲"，然后立即回到主线，不提前展开长篇推导。
- 属于与论文主线无关的问题：用一句话说明"这与本篇主线关系不大"，不展开长篇解释，可在文末记入【待办清单】。
- 属于理解当前内容所必需的问题：才当场完整讲清（定义 + 例子 + 直觉，必要时配数字）。
- 当读者连续发散提问时，主动说"我们先把主线推到第 X 节"，把话题收束回主线。
- 每次回复若产生了延后内容，在文末加一小节【待办清单】列出即可，不占用主线篇幅。

【讲解风格】

- 易混概念用表格；抽象概念用类比 + 数字例子；关键设计讲"为什么"。
- 按顺序记忆的知识，先讲根本原因或分类依据，让清单从原理里自然推导出来。
- 主动提醒常见坑（歧义译文、论文内部数据不一致、易混符号、易混概念如 layer vs sublayer）。
- 正文里的 **…** 粗体慎用于中文句末或紧贴中文标点的位置（实测星号会漏出）；预告句/收尾句用普通文本或分节标题，不用粗体包裹整句。
- 我指定重点时，其他内容一句话带过，不平均用力。

【数学公式渲染要求（硬性）】

- 行内符号一律用 Unicode 字符（hₜ , xₜ , dₖ , √ , ᵀ , ·），符号后若紧跟标点就在符号与标点之间加一个半角空格（英文原文引用同样处理）；只有独立成行的重点公式才用 $$…$$ 块级；输出前自查：正文里不得出现裸的 $、\、下划线。

## 附录 A：为什么聊天里行内 $…$ 不渲染（根因备忘）

本机 Codex 桌面版的聊天渲染器把 markdown 管线配置为 remarkPlugins: [[remarkMath, { singleDollarTextMath: false }]], rehypePlugins: [rehypeKatex]，即行内 $…$ 被硬编码禁用，只有 $$…$$ 可用；config.toml 无此开关，应用为签名包不可改。→ 行内符号用 Unicode，独立公式用 $$…$$。
